**[在线试玩](https://catcityletters.xyz/)** · [燕园版本说明](北大猫协版说明.md) · [来源与复制校验清单](source_manifest.json)

这是一个以校园猫咪救助为主题的公益叙事网页游戏，包含猫城原版与燕园猫协版。现有版本支持地图探索、固定规则下的资源分配、分支事件、阶段性结局、本地存档、三周续玩、成就与图鉴，以及 3 分钟演示模式。原项目由 AI 辅助实现；当前居民反馈使用本地预写文本，未接入在线 AI。

本仓库保留完整游戏源码、18 张猫咪头像素材、已有 `dist/` 发布目录、原打包文件、测试与说明；未包含 Git 历史、部署账号配置或无关科研文件。原版制作提交集中于 2026 年 10 月 14—17 日，本次仅整理为可浏览的 GitHub 作品。

## 目标

用一个 3 分钟可演示的单机网页游戏，展示“有限资源下的具体救助选择如何改变猫咪命运”，并说明 AI 只生成受控反馈，不替代游戏规则。

## 负责人

- A：事件、分支、结局、路演表达
- B：`engine.js` 状态机、资源、存档校验、AI 降级接口位置
- C：`style.css` 视觉、`app.js` 交互与演示包装

## 输入与输出

- 输入：玩家选择、固定事件数据、猫咪状态、站内资源
- 输出：资源变化、猫咪状态变化、居民反馈、下一日事件、七日阶段性结局

## 运行

直接双击 `index.html`，或在目录运行：

```powershell
python -m http.server 4173
```

再打开 `http://localhost:4173/`。页面只依赖浏览器和 `localStorage`，无安装步骤、无网络核心依赖。

## 已完成标准

- 6 只猫、校园地点、7 天流程
- 15 个固定事件，包含资源、猫咪状态、关系变化和备用反馈
- 小黑完整主线：投喂建立信任 / 低压力治疗 / 紧急转运 / 未完成交接
- 至少 2 个结局，结局按固定规则计算
- 6 种资源或状态：资金、猫粮、医疗名额、行动点、社区信任、志愿意愿
- 本地存档与回放校验；篡改存档会被拒绝
- AI 增强点预留为居民反馈，接口失败仍使用固定文本
- 校园遇见地图：点击有“新”标记的小猫触发当天来信；无新来信时可打开档案
- 六只猫各有阶段性结局来信，可在第七天拆开阅读并导出七日手记
- 社区公告栏与每日交接目标会随社区信任、志愿者意愿和当天事件变化
- 3 分钟演示模式只保留小黑主线与必要交接节点，适合路演现场
- 首次进入的新手关会分四步解释地图、档案、行动代价和每日交接，也可随时从“新手指引”重新打开
- 每次选择后都会显示资源、健康、信任、压力的实际前后变化，并在侧栏短暂闪动提示
- 七日结束后可继续下一周：保留部分资金、猫粮和救助材料，并解锁第二周的新猫咪“栗子”与后续事件
- 每局可选择不同开局策略：慢救主义、医疗优先、夜行小队；策略改变资源结构和可行路线

## 三分钟演示路径

1. 第 1 天小黑选择“放下食物，退到远处”，强调信任与压力。
2. 第 2 天继续低干扰准备，展示资源变化和状态卡。
3. 第 4 天选择“进行低压力转运与检查”，说明信任门槛来自前置选择。
4. 其余事件快速选择，展示奶糖身份线、花卷与雨点成对照护、小月安静照护。
5. 第 7 天查看六只猫的阶段性去向，落到“救助不会在结局停止”。

## 决策记录 · 2026-10-14

| 决策 | 原因 | 放弃方案 | 影响 | 状态 |
|---|---|---|---|---|
| 使用 buildless HTML/CSS/JS | 三人团队最快交付，现场断网可运行 | 框架、数据库、后端服务 | 可直接双击或静态部署 | 已实现 |
| 规则全部固定在 `data.js` 与 `engine.js` | 保障可解释、可测试 | 让 AI 决定事件和数值 | AI 只负责受控反馈 | 已实现 |
| 结局使用“阶段性去向” | 避免把公益简化为成功/失败 | 单一好结局、收集式评分 | 未完成事项进入交接 | 已实现 |

## 下一步

接入真实 AI 时，只替换居民反馈函数：输入限制为猫咪状态摘要与玩家选项，输出限制为一段短文本；任何解析失败都回退到事件卡的 `fallback` 字段。不要让模型写入规则状态。
